## 一、通用视觉规则（所有视图共用）

- **只有两处使用强调色**：原文引用条的左侧竖线、对话视图的发送按钮。其余一律中性色。
- **左侧竖线只代表「这是书里的原文」**，其他元素不得使用左边线。
- 原文使用阅读字体 `--font-text`，界面文字使用 `--font-interface`。
- 不使用 emoji 图标；需要图标时用细线条 SVG。
- 不使用聊天气泡。对话按「问答文档」排版。
- **用户的话和 AI 的话必须在视觉上可区分**：AI 生成的内容一律带「AI」标签。
- 状态用**形状**区分，不只靠颜色（见第三节）。
- 只使用 Obsidian CSS variables，浅色 / 深色主题都必须可读。

| 用途 | 变量 |
|---|---|
| 背景 | `--background-primary` / `--background-secondary` |
| 边框 | `--background-modifier-border` |
| 文字 | `--text-normal` / `--text-muted` / `--text-faint` |
| 强调 | `--interactive-accent` / `--text-on-accent` |
| 已解决 / 已保存 | `--color-green` |
| 未解决 / 未保存 | `--color-orange` |
| 原文淡底色 | `color-mix(in srgb, var(--interactive-accent) 8%, var(--background-primary))` |

侧栏顶部用分段切换统一三个视图：**对话 / 思考树 / 导图**。

```
查看原文   之前的讨论 2        ● 未保存 [保存]
─────────────────────────────────────────────
我
为什么呢？                               ← 加粗，无卡片
AI
正文回答，完整 Markdown……
┌ 一句话  理论告诉你市场"应该"怎样…… ┐   ← 浅底色摘要块
─────────────────────────────────────────────
┌──────────────────────────────────────┐
│▍带上这段原文提问              × 不使用 │ ← 仅待提问时出现
│▍我们认为无效性是存在的……              │
│ 输入问题（默认约 3 行，自动增高）       │
│ Ctrl + Enter 发送              [发送]  │
└──────────────────────────────────────┘
        仅发送所选原文与本次对话 · 设置
```

要点：

- 待提问的原文放在 Composer 内部顶部；发送第一个问题后消失，原文收进对话头的「查看原文」，两份原文不得同时出现。
- 「对话只保留到关闭 Obsidian」的长期说明删除，只在空状态出现一次；改为对话头的「● 未保存 / ✓ 已保存」状态。
- 保存后不长期显示文件路径，改为消息区底部一行「已写入读书笔记 · 打开笔记」。
- 「之前的讨论」展开为可扫描的列表：topic、第一个问题、一行原文、轮数与时间、保存状态。不展开成完整正文。
- AI 回答中以「一句话：」开头的段落渲染为摘要块，只改样式，不改内容。
- 预留：将来保存时的「我的理解」确认面板（AI 起草 → 这就是我的理解 / 修改 / 暂不总结），位于对话区底部。V1 不实现。

## 三、思考树侧栏视图（Phase 4 方向）

### 扫描态（默认）

```
[对话] [思考树] [导图]                         [⋯]
《投资最重要的事》
6 条讨论 · 2 条未解决 · 1 条未总结   (只看未解决)

▼ 第1章 学习第二层次思维                        1
   突破常规具体指什么                     ◌ 未总结
   AI 不同还不够，判断还必须比共识更正确。
   1 问
▼ 第2章 理解市场有效性及局限性                  2
   理论与实践为何背离：反身性与自我否定    ✓ 已解决
   理论不是因为错了才失效……           我写的
   2 问
   为什么不能连续识别市场错误并套利       ○ 未解决
   错误一旦被利用就会消失……     AI 起草 · 我改过
   3 问
▶ 第5章 理解风险                                3
```

- 每条 thread 默认只占 2–3 行：标题、一行理解、问题数。
- 有「我的理解」时显示用户理解并标注来源；没有时才显示 AI 一句话，并以「AI」开头。
- 状态符号：`✓` 已解决 / `○` 未解决 / `◌`（虚线圆）未总结。**未总结 ≠ 未解决**。
- 「只看未解决」筛选为可选项。

### 展开一条 thread

```
   理论与实践为何背离：反身性与自我否定    ✓ 已解决
   原文
   ▍理论和实践在理论上没有什么不同……
   问题链
   Q1   为什么呢？
     ↳ Q2  实践要面对"反身性/自我否定"，这是什么？
   ┌ 我的理解  我写的 ───────────────────┐
   │ 理论不是因为错了才失效……            │
   └─────────────────────────────────────┘
   AI 一句话  理论告诉你市场"应该"怎样……
   查看 PDF 原文   继续讨论   打开笔记
```

- 问题链只显示问题，不展开 AI 完整回答；完整内容通过「继续讨论」或「打开笔记」查看。
- 「查看 PDF 原文」跳回原文位置，「继续讨论」切换到对话视图并载入该 thread。
- 从思考树补写「我的理解」属于新入口，需在 Phase 3 设计时一并决定，本视图不预先实现。

## 四、思考树 Markdown 存档（新需求）

目标：思考树在 vault 中有一份真实的 Markdown 文件。不打开插件、甚至卸载插件后，存档依然可读、可搜索、可双链、可用大纲查看。

架构位置：与侧栏视图、Mindmap 并列，是 Thought Tree Model 的另一种输出。**只读取 Model，不得自行解析 Reading Note。**

规则：

1. **存档是副本，不是源数据。** 内容以读书笔记为准；存档内的修改会在下次生成时被覆盖。
2. **单独文件**，不向读书笔记插入任何内容。文件名示例：`投资最重要的事 · 思考树.md`，与读书笔记放在同一文件夹（可在设置中调整）。
3. **手动触发**：命令「生成 / 更新思考树存档」，以及思考树视图中的同名按钮。不做后台自动写入。
4. **只覆盖自己生成的文件**：通过 frontmatter 标记识别。同名文件若不是 Backleaf 生成的，绝不覆盖，提示用户改名或换位置。
5. 每条 thread 带链接跳回读书笔记中对应的标题位置。
6. 「我的理解」与「AI 一句话」必须分开标注，延续「AI 结论 ≠ 用户理解」原则。
7. frontmatter 中的标识字段会写入用户 vault，属于持久化标识，**必须在 Phase 2 插件改名之后再实现**。

示例（字段名为示意，以实现时的设计为准）：

```markdown
---
backleaf: thought-tree
book: 投资最重要的事
source: "[[投资最重要的事]]"
generated: 2026-10-01
---

> 本文件由 Backleaf 根据 [[投资最重要的事]] 自动生成。
> 请在读书笔记中修改内容，本文件在更新时会被覆盖。

# 《投资最重要的事》思考树

6 条讨论 · 2 条未解决 · 1 条未总结

## 第1章 学习第二层次思维

### 突破常规具体指什么 ◌
- 原文：你不可能在和他人做着相同事情的时候期待胜出……
- Q1 突破常规具体指？
- AI 一句话：不同还不够，判断还必须比共识更正确。
- [[投资最重要的事#突破常规具体指什么|查看完整讨论]]

## 第2章 理解市场有效性及局限性

### 理论与实践为何背离：反身性与自我否定 ✓
- 原文：理论和实践在理论上没有什么不同，但在实践中却截然相反。
- Q1 为什么呢？
  - Q2 实践要面对"反身性/自我否定"，这是什么？
- 我的理解（我写的）：理论不是因为错了才失效，而是大家按它行动以后，市场本身变了。
- AI 一句话：理论告诉你市场"应该"怎样，机会藏在它和实际之间的缝隙里。
- [[投资最重要的事#理论与实践为何背离：反身性与自我否定|查看完整讨论]]
```

格式说明：

- 状态符号直接写在讨论标题末尾（`✓` 已解决 / `○` 未解决 / `◌` 未总结），不单独占一个节点。
- 问题直接挂在讨论标题下，不加「问题链」这一层；追问用缩进表示。
- 这样在导图中层级最少：书 → 章 → 讨论 → 细节。

在「我的理解」上线（Phase 3）之前，存档中只出现 AI 一句话，状态统一为「未总结」。

已验证（2026-10-01，Clean Test）：现有 Mindmap 插件可直接把这种结构画成导图，存档中的链接在导图里能跳回读书笔记。

存档被编辑的风险：导图节点可直接 Rename / Delete / Add child，节点菜单中的「查看完整笔记」弹窗也可编辑并保存当前文件的对应行。这些修改都会改动存档文件，并在下次更新时被覆盖。存档开头的提醒需覆盖这些入口；是否在导图中提示「此文件为自动生成」，实现时再定。
